# Проверка ML

Все новые проверки выполняются на арендованном GPU-сервере Brev; Mac используется для кода, SSH и просмотра отчётов. Серверные команды и профиль: [ML_SETUP.md](../docs/ML_SETUP.md).

`audio/`, `results/` и `.venv/` исключены из Git. Тестовые записи не попадают в публичный репозиторий автоматически.

Первый рубеж: реальный вызов Whisper + pyannote на короткой записи, минимум два голоса, проверка текста и интервалов человеком. Команда: `scripts/run_ml_checkpoint.py`; подробности в `docs/ML_SETUP.md`.

Для каждой записи фиксируем:

| Поле | Что записать |
| --- | --- |
| Язык | RU, KZ либо RU/KZ |
| Модели и железо | Точные веса/ревизии, квантизация, CPU/GPU, память |
| Время | ASR, диаризация, извлечение, весь проход |
| Реплики | Пропуски, искажения имён, чисел и отрицаний |
| Голоса | Проверенные интервалы, ошибочные слияния/разделения |
| Поручения | Правильные, пропущенные, лишние; исполнитель и срок отдельно |
| Источники | Ссылка ведёт к реальному подтверждающему фрагменту |

Предоставленные записи русскоязычные по эталонным текстам. Они не заменяют самостоятельные тесты казахского и смешанной речи. Для последних записать вымышленные диалоги минимум двух людей, с явным поручением, отсутствующим сроком и уточнением срока.

Сначала проверить извлечение на эталонном тексте, затем на ASR-транскрипте. Разница помогает отделить ошибки распознавания от ошибок извлечения. Примеры задания содержат 10 строк поручений в первом summary и 6 во втором; строки могут объединять несколько обязательств, поэтому оценивать смысл, не только число объектов.

Модульные тесты с подменой inference помечаются отдельно. Реальная конвертация FFmpeg не является тестом распознавания. Статус `completed` в отчёте означает исполнение моделей, а качество до ручной сверки остаётся непроверенным.
