# Хаттама — проверяемые протоколы встреч

Хаттама помогает секретарю проверить проект протокола: сопоставить поручения с исходными репликами, исправить исполнителей и сроки, сохранить правки, утвердить результат и скачать DOCX. Реестр показывает исполнение и локальные напоминания.

Корпоративный интерфейс включает обзор встреч и сроков, светлую молочную тему с шалфейным акцентом и тёмную графитовую с винным. Тема переключается в навигации и сохраняется в браузере. В редакторе поручения можно сверять с исходными репликами; сохранение и утверждение доступны в закреплённой панели. Подробности оформления и проверки — [frontend/README.md](frontend/README.md).

**Работающий demo использует вымышленные заранее подготовленные данные. Это проверка интерфейса и backend, а не качества моделей.** На проверенной машине ASR, Ollama и диаризация недоступны. Полный путь из настоящей речи пока не подтверждён.

## Архитектура

```text
Браузер: React + TypeScript
    │ /api — Vite proxy в разработке; тот же FastAPI в production
    ▼
FastAPI → SQLite + файлы → один фоновый обработчик
    ├─ demo: подготовленная fixture, без inference
    ├─ текст: локальная Ollama → проект протокола
    └─ запись: FFmpeg → Whisper → pyannote → Ollama
    ▼
Проверка человеком → сохранение с revision → утверждение → DOCX / реестр
```

Модели исполняются на машине backend либо явно настроенном частном сервере команды. GPU в Brev — планируемое размещение, в этой проверке не использовалось. Браузер не требует ключей OpenAI/NVIDIA; автоматического облачного fallback нет. [HTTP-контракт](contracts/README.md) сохранён без изменений.

## Требования и проверенные версии

- Python **3.12.14**. Системный Python 3.9 не подходит к текущему backend.
- Node.js **24.19.0**, npm **10.9.4**; для frontend указан Node >=22.
- React **18.3.1**, TypeScript **5.6.3**, Vite **6.4.3**, Playwright **1.63.0**. Точные версии фиксирует `frontend/package-lock.json`.
- FastAPI **0.141.1**, uvicorn **0.53.0**, python-docx **1.2.0**, python-multipart **0.0.32**.
- macOS / ARM64, Google Chrome. Для демо GPU и веса моделей не нужны.

Backend requirements задают диапазоны, не lock-файл. Приведённые версии — фактическое окружение проверки, а не гарантия всех сочетаний зависимостей.

## Быстрый запуск demo без моделей

Из корня репозитория, первый терминал:

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -r backend/requirements.txt
.venv/bin/uvicorn backend.app.main:app --host 127.0.0.1 --port 8000
```

Во втором терминале:

```bash
cd frontend
npm ci
npm run build
npm run dev
```

Открыть [интерфейс](http://127.0.0.1:5173), нажать **«Открыть демо»**. Каждый клик создаёт отдельную встречу. В браузере отображается «Вымышленные данные · готовый пример». Недоступность моделей видна в диагностике, но не мешает серверному demo-route.

После `npm run build` FastAPI сам раздаёт `frontend/dist`: можно открыть [готовую сборку](http://127.0.0.1:8000) без Vite. Команда `npm run preview` служит только для просмотра статики; API proxy в ней не настроен.

По умолчанию данные хранятся в `data/`. Для отдельной проверки запускайте backend с `DATA_DIR=/tmp/hatama-qa`. Не удаляйте каталог рабочих данных ради повторной демонстрации. Корневой `.env` загружается автоматически; переменные окружения имеют приоритет. Также доступен запуск `.venv/bin/python -m backend`. Vite и backend по умолчанию слушают только `127.0.0.1`.

Backend участника 2 принят в `main` через PR #1 и объединён с frontend. Стык проверен по [передаче backend](backend/INTEGRATION_HANDOFF.md); HTTP-схема не менялась. Результаты совместной проверки — [QA](docs/QA.md).

## Сценарий пользователя

1. «Новая встреча»: название, дата, часовой пояс, имена. Для записи — файл WAV/MP3/M4A/MP4/WebM/OGG/FLAC до 100 МБ и подтверждение уведомления участников. Текстовый импорт отдельно обозначен как обработка без ASR.
2. При обработке показывается реальная стадия каждые 3 секунды. При ошибке запись остаётся в списке; после исправления конфигурации создайте новую встречу с тем же входом.
3. В готовом протоколе проверить итог; раскрыть «Участники и голоса» для ручного сопоставления имён. Нажать на источник у поручения: исходная реплика выделяется и получает фокус. Для настоящей записи доступно воспроизведение с её времени. Историю и поиск открывает кнопка «Все встречи».
4. Исправить задачу, исполнителя, календарную дату и отдельно исходную формулировку срока. Неизвестная дата остаётся пустой. Причина проверки снимается только кнопкой ручного подтверждения.
5. «Сохранить» отправляет правки с исходной `revision`. При конфликте черновик остаётся в браузере: можно скачать JSON, открыть серверную версию и вручную перенести правки.
6. «Утвердить протокол» доступно после сохранения, заполнения задач/исполнителей и снятия причин проверки. Только утверждённая сохранённая версия экспортируется в DOCX.
7. На экране «Задачи» выбрать Все / В работе / Просрочено / Выполнено и завершить поручение. Напоминания доступны локально; дополнительный Telegram-бот подключается отдельно по [инструкции](docs/TELEGRAM.md) и по умолчанию выключен.

Polling и переходы между экранами не затирают черновики. При закрытии/перезагрузке вкладки браузер предупреждает о несохранённых правках. Черновики находятся в памяти вкладки: они не переживают принудительное закрытие браузера. Сохраняйте их на сервере. Редактирование утверждённого содержания блокирует экспорт; сохранение снимает утверждение. Завершение задачи само по себе его не снимает.

## Настоящая обработка — отдельная настройка

Владелец ML: участник 1, [инструкции и критерии](docs/tasks/01_ML_GPU.md). Следующие шаги описывают требования текущего кода; успешный GPU-прогон здесь **не проверен**.

1. На выбранной машине backend установить FFmpeg и отдельно библиотеки:

   ```bash
   .venv/bin/python -m pip install -r backend/requirements-ml.txt
   ```

2. Отдельно подготовить локальные веса faster-whisper large-v3, полный локальный каталог pyannote Community-1 и Ollama с Qwen3-8B. Скачивание и принятие условий моделей выполняются отдельно; inference автоматически веса не скачивает. Для установленной Ollama подготовка модели: `ollama pull qwen3:8b`.
3. Перед запуском backend задать проверенные на своей машине пути и устройство:

   ```bash
   export OLLAMA_BASE_URL=http://127.0.0.1:11434
   export OLLAMA_MODEL=qwen3:8b
   export ASR_MODEL=/absolute/path/to/faster-whisper-large-v3
   export ASR_DEVICE=cuda
   export ASR_COMPUTE_TYPE=float16
   export DIARIZATION_MODEL_PATH=/absolute/path/to/pyannote-community-1
   .venv/bin/python scripts/check_models.py
   .venv/bin/uvicorn backend.app.main:app --host 127.0.0.1 --port 8000
   ```

   Пути — шаблоны, их нужно заменить. CUDA/torch и объём VRAM подтверждает участник 1. CPU по умолчанию использует `int8`; конфигурация GPU выше не является замером производительности. Альтернативный ASR требует одновременно `WHISPER_CPP_BIN` и `WHISPER_CPP_MODEL`; диаризация всё равно обязательна.
4. Проверить [health](http://127.0.0.1:8000/api/health). `true` означает только доступность зависимостей/моделей; качество нужно оценивать отдельно.
5. Для удалённой машины предпочтителен SSH-туннель к backend. Авторизации пользователей в MVP нет; публичное размещение без дополнительного ограничения доступа не предусмотрено.

Текущее ограничение ML: текст до 80 000 символов, аудио до часа. Веса, точные CUDA/torch-версии и задержка на GPU пока не зафиксированы. Не включайте ключи и частные записи в Git.

## Проверки

Для полного автоматического прогона без готовых моделей есть отдельный
[ML-stub стенд](docs/TESTING_WITH_ML_STUBS.md): установите
`backend/requirements-dev.txt` в `.venv`, затем в `frontend/` выполните
`npm ci` и `npm run test:integration`. Команда сама собирает UI и запускает
изолированный тестовый backend. Заглушки явно помечены в UI/DOCX и не включаются
в обычном запуске приложения. Этот прогон проверяет интеграцию, не качество ML.

```bash
cd frontend
npm ci
npm run build
npx playwright install chromium
npm run test:e2e
```

Перед E2E запустить backend на отдельной базе и Vite командами выше. Можно использовать установленный Chrome: `npx playwright install ffmpeg`, затем `PLAYWRIGHT_CHANNEL=chrome npm run test:e2e`. `UI_BASE_URL=http://127.0.0.1:8000` проверяет production-сборку. Тесты создают вымышленные записи и меняют только их; негативные ML-тесты пропускаются, если необходимые модели доступны.

Из корня:

```bash
PYTHONPATH=backend .venv/bin/python -m unittest backend.tests.test_ml -v
.venv/bin/python scripts/check_models.py
```

Результаты, границы проверок и дефекты приведены в [docs/QA.md](docs/QA.md). Сценарий трёхминутной защиты и резервное видео — [docs/demo.md](docs/demo.md).

## Статус и ограничения

Реализованы frontend-проверка, сохранение, конфликты revision, утверждение, получение DOCX, реестр, локальные напоминания и честные ошибки. Реальный ML-пайплайн существует в коде, но на этой машине не готов. Нет доказанного качества RU/KZ/RU-KZ, замеров точности, дообучения или производительности GPU.

После интеграции backend DOCX содержит подтверждённую дату и исходную формулировку срока. Экспорт использует снимок утверждённой версии; отметки исполнения увеличивают revision, но не меняют этот снимок. Ранее найденные проблемы экспорта даты и версионирования исполнения устранены участником 2.

Имена требуют ручного сопоставления, неоднозначные сроки — проверки. Это импорт файлов, а не бот Zoom/Meet/Teams. PDF, подключение к платформам и СЭД пока не реализованы. [Telegram](docs/TELEGRAM.md) поддерживает одноразовую привязку участников, назначения после утверждения, напоминания и «Выполнено»; проверен с имитацией Bot API, живая отправка требует токена BotFather и тестового чата.
