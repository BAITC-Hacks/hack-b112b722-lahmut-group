# ML: подготовка и проверка на GPU-сервере

Владелец — участник 1. HTTP-контракт не менялся. `process_audio` и `process_text` возвращают результат из реальных моделей; `probe` проверяет предварительную готовность без скачивания и без обещания качества.

## Где выполняются проверки

По указанию пользователя от 2026-09-23 все новые тесты выполняются на арендованном сервере Brev `hatama-ml-gpu` (`icwi6fybo`), включая модульные тесты и полный ML-проход. Mac используется для редактирования кода, Git, SSH и просмотра результатов. Приведённые ниже команды окружения, подготовки моделей и тестов выполняются **в SSH-сессии сервера**. Исторические замеры Mac сохранены только как сведения о предыдущем этапе.

Подключение: `brev shell hatama-ml-gpu` либо `ssh hatama-ml-gpu` после обновления SSH-конфигурации Brev. Перед проверкой сверить серверный checkout с `origin/main` и записать `git rev-parse HEAD`; при локальных изменениях сначала разобрать их. GPU-проверка начинается с подтверждения Linux, `nvidia-smi` и доступности CUDA.

## 1. Окружение

Команды выполняются из корня репозитория на GPU-сервере. Используется отдельное окружение для backend и ML:

```bash
/home/ubuntu/.venv/bin/python -m venv eval/.venv
eval/.venv/bin/python -m pip install torch==2.8.0 torchaudio==2.8.0 --index-url https://download.pytorch.org/whl/cu126
eval/.venv/bin/python -m pip install -r backend/requirements.txt -r backend/requirements-ml.txt
eval/.venv/bin/python -m pip install torchcodec==0.7.0
eval/.venv/bin/python -m pip check
ffmpeg -version
```

Для GPU нужны рабочий NVIDIA driver, совместимые torch/CUDA, cuBLAS и cuDNN. Фактические версии сохраняются в отчёте прогона. Проверка:

```bash
nvidia-smi
uname -s
eval/.venv/bin/python -c 'import platform, torch; assert platform.system() == "Linux", "Run on the GPU server"; assert torch.cuda.is_available(), "CUDA unavailable"; print(torch.__version__, torch.version.cuda, torch.cuda.get_device_name(0))'
```

Проверка должна показать Linux и доступную NVIDIA GPU. Установленный без фиксации версий `torchcodec 0.16.0` несовместим с `torch 2.8.0` и выдавал предупреждение `libnvrtc.so.13`; 0.7.0 импортируется без него. Версии зависимостей зафиксировать командой `eval/.venv/bin/python -m pip freeze > eval/results/server-requirements.txt` (предварительно создать `eval/results/`). Для иной версии драйвера подбирать совместимую сборку отдельно.

## 2. Модели скачиваются отдельно

Для pyannote владелец аккаунта принимает условия доступа к [Community-1](https://huggingface.co/pyannote/speaker-diarization-community-1) и настраивает токен с минимальным доступом через интерактивный вход. Токен не включать в командную строку, Git или отчёт:

```bash
eval/.venv/bin/hf auth login
eval/.venv/bin/python scripts/prepare_models.py --output models/gpu
```

Скрипт скачивает собственно веса из Hugging Face и фиксирует commit SHA в `models/gpu/manifest.json`. При недоступном gated-репозитории он завершается ошибкой; не принимает условия аккаунта автоматически.

`--only asr` позволяет готовить незакрытые ASR-веса, пока владелец аккаунта настраивает pyannote. Повторный запуск возобновляет скачивание. Для воспроизведения на другой машине передать сохранённые SHA в `--asr-revision` и `--diarization-revision`.

## 3. Настройки inference

GPU-профиль сервера:

```bash
export ASR_MODEL="$PWD/models/gpu/asr"
export DIARIZATION_MODEL_PATH="$PWD/models/gpu/diarization"
export ASR_DEVICE=cuda
export ASR_COMPUTE_TYPE=int8_float16
export ASR_GAP_RECOVERY=true
```

Веса large-v3, pyannote и LLM освобождаются между тяжёлыми этапами. Диаризация не требует имени участника, однако привязка голоса к имени требует контекста и проверки человеком.

Для полного протокола установить и запустить официальный Ollama на той же машине, затем отдельно скачать модель:

```bash
ollama pull qwen3:32b
export OLLAMA_BASE_URL=http://127.0.0.1:11434
export OLLAMA_MODEL=qwen3:32b
export OLLAMA_THINKING=false
eval/.venv/bin/python scripts/check_models.py --strict
```

Если `probe` сообщает отсутствие LLM, первый ASR/диаризация checkpoint всё ещё можно выполнять: он не зависит от Ollama.

32B занимает около 20 GB на диске в Ollama и проверена на L40S с 48 GB VRAM. Профиль `.env.example` предназначен для этого сервера. Значение по умолчанию в коде остаётся `qwen3:8b` для совместимости; выставляйте `OLLAMA_MODEL` явно. Thinking и отдельный второй LLM-проход не показали достаточного выигрыша на встречах и не входят в выбранный профиль.

`ASR_GAP_RECOVERY=true` включает до трёх дополнительных коротких ASR-проходов: только внутренние пробелы 1–10 секунд, где диаризация покрывает не менее половины интервала речью. Низкая средняя уверенность и спорные границы отклоняются; восстановленная речь всегда помечается для проверки. Без переменной режим выключен. Это исправляет наблюдённый пропуск, но не гарантирует обнаружение всех ошибок распознавания.

Endpoint Ollama по умолчанию loopback; допускается явно заданный приватный IP. Публичные адреса, прокси и redirect запрещены в ML-адаптере. Веса должны быть локальными; при их отсутствии inference не скачивает их автоматически. Для проверки полного офлайн-режима ограничить исходящую сеть на машине и повторить запуск после подготовки всех весов.

## 4. Первая контрольная точка: настоящие 60 секунд

Запись помещается в игнорируемую Git папку `eval/audio/`. Предоставленная запись №1 скачана как `eval/audio/meeting-1.mp3`; если файл отсутствует на другом компьютере, скачать по исходной ссылке из задания. Дату встречи взять из известных исходных данных. Если она не установлена, для smoke-теста можно задать условную дату, но это не основание для проверки относительных сроков.

```bash
eval/.venv/bin/python scripts/run_ml_checkpoint.py eval/audio/meeting-1.mp3 \
  --occurred-at 2026-09-23 --seconds 60 --min-speakers 2 \
  --output eval/results/meeting-1-speech.json
```

Скрипт последовательно выполняет FFmpeg, настоящее распознавание и настоящую диаризацию. Сохраняет сегменты, интервалы голосов, SHA-256 входа, названия моделей, версии библиотек и время каждого этапа. `--min-speakers` проверяет результат, но не заставляет модель вернуть заданное число голосов.

Статусы отчёта:

- `completed` — inference завершён и минимальное число голосов найдено. Это ещё не экспертная оценка качества.
- `needs_review` — inference выполнен, но число голосов не соответствует ожиданию.
- `failed` — конкретный этап завершился ошибкой.

Проверка человеком обязательна: текст совпадает с услышанным, интервалы соответствуют сменам голосов, имена/числа не потеряны. Поле `quality_review` остаётся `not_performed`, пока разметка не проверена отдельно. Число найденных кластеров само по себе не доказывает верную диаризацию.

`--offset 60` выбирает другой фрагмент; временные метки в JSON всё равно относятся к исходному файлу. Путь результата должен быть новым: старые результаты не перезаписываются.

## 5. Полный проход и языки

После первого speech-checkpoint:

```bash
eval/.venv/bin/python scripts/run_ml_checkpoint.py eval/audio/meeting-1.mp3 \
  --occurred-at 2026-09-23 --seconds 3600 --min-speakers 2 --full --diagnostics \
  --output eval/results/meeting-1-full.json
```

`--participants` принимает JSON-массив Participant[] из общего контракта. Без подтверждённой связи имя/голос ассистент не должен уверенно назначать поручение только по кластеру.

Проверить обе предоставленные записи и отдельные короткие RU/KZ/RU-KZ сценарии. Эталонное summary не включать во вход модели. Не обучать модель на тестовых встречах.

Текущие ограничения: Whisper.cpp использует автоопределение языка, но без словных меток сохраняет фразовую точность сопоставления. Faster-whisper использует словные метки и переопределение языка по сегментам. Это повышает пригодность к смешанной речи, но не гарантирует качество. Даты без года, относительные и событийные сроки требуют подтверждения. Слияние повторов в постобработке консервативное: перефразированные дубли и противоречия проверяет секретарь.

## 6. Регрессионные проверки без моделей на сервере

```bash
PYTHONPATH=backend eval/.venv/bin/python -m unittest \
  backend.tests.test_ml backend.tests.test_ml_alignment \
  backend.tests.test_ml_extraction_quality backend.tests.test_ml_diagnostics \
  backend.tests.test_ml_gap_recovery -v
```

Проверяются источники поручений, сроки, сопоставление имён, запрет внешних endpoints, обрезанный JSON, сохранение полного текста и смена говорящего внутри предложения. Эти проверки дополняют реальный inference, а не заменяют его.

## 7. Сравнение LLM на одинаковом входе

```bash
eval/.venv/bin/python scripts/evaluate_extraction.py \
  --cases eval/text_quality_cases.json --model qwen3:32b \
  --output eval/results/suite-qwen32.json
eval/.venv/bin/python scripts/evaluate_extraction.py \
  --checkpoint eval/results/meeting-1-full.json --model qwen3:32b \
  --output eval/results/meeting-1-extraction.json
```

Поле `expected` из набора никогда не передаётся модели. Сохранённый checkpoint позволяет сравнить извлечение на одном и том же тексте, отдельно от качества ASR. Скрипт фиксирует входной и программный SHA-256, digest модели, время и фактический ответ. `--thinking` — только отдельный эксперимент. `scripts/evaluate_refinement.py` сохраняет исследовательский второй проход; основной backend его не вызывает.

`--diagnostics` у speech-runner сохраняет оригинальные ASR-слова, вероятности, обе аннотации диаризации и попытки восстановления. Времена относятся к исходной записи, в том числе при `--offset`; внутренние диагностические поля не добавляются в HTTP-контракт. Для VAD A/B доступен `scripts/compare_asr_vad.py` (только Linux/CUDA); исходные тексты и эталоны не используются как подсказка модели.
