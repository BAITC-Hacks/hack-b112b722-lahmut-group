## Окружение и воспроизведение

macOS ARM64; Python 3.12.14; Node 24.19.0; npm 10.9.4; Vite 6.4.3; Playwright 1.63.0. Версии backend — в README. Тестовый backend запущен с `DATA_DIR=/tmp/hatama-ui-qa`, отдельной базой без пользовательских данных. Проверка браузера выполнена Playwright в настоящем Google Chrome 153.0.8010.53. Встроенный инструмент управления браузером Codex не стартовал из-за ошибки sandbox; это не было заменено проверкой только HTTP.

```bash
# Из корня, отдельный терминал
DATA_DIR=/tmp/hatama-ui-qa .venv/bin/uvicorn backend.app.main:app --host 127.0.0.1 --port 8000

# Другой терминал
cd frontend
npm ci
npm run build
npm run dev

# Третий терминал
cd frontend
npx playwright install ffmpeg
PLAYWRIGHT_CHANNEL=chrome npm run test:e2e
# Для production-сборки, которую раздаёт FastAPI:
UI_BASE_URL=http://127.0.0.1:8000 PLAYWRIGHT_CHANNEL=chrome npm run test:e2e
```

В этой сессии системных Node/npm и готовой `.venv` не было. Использованы Node из bundled runtime Codex, npm 10.9.4 во временном каталоге и Python venv `/tmp/hatama-ui-venv`. Установка зависимостей, запуск backend по модулю из README, `npm ci` и сборка выполнены фактически. Команда `python3.12` в README предполагает установленный Python 3.12 на машине читателя.

Контракт `contracts/README.md` не менялся. PATCH встречи передаёт `{revision, summary, participants, actions}`, approve — `{revision}`. Пустая дата остаётся `null`, исходный срок сохраняется независимо. Все маршруты идут через `/api`; Vite proxy — `127.0.0.1:8000`.

Backend участника 2 получен через уже принятый PR #1 (`e710e32`); его [передача](../backend/INTEGRATION_HANDOFF.md) прочитана. Требуемые исправления UI — инициализация результата обработки, revision черновика, обновление исполнения, правки после утверждения и честная диагностика — реализованы. Прямой разговор с участником не подменяется этим файловым согласованием.

Закрыты два ранее зарегистрированных замечания:

1. `backend/app/export.py` выводит подтверждённую дату вместе с исходным сроком. Проверочный кейс: `due_date="2020-01-01"`, исходный `due_text="К 25 сентября 2026 года"`; DOCX должен содержать обе строки.
2. `PATCH /actions/{id}` увеличивает revision при смене исполнения. Утверждённый DOCX остаётся снимком протокола, а устаревшие правки получают 409.
