# Frontend Хаттамы

Корпоративное рабочее пространство для секретаря и руководителя: обзор встреч и сроков, проверка протокола по исходным репликам, сохранение, утверждение, DOCX и контроль поручений.

## Запуск

Node.js >=22. В проверке использованы Node 24.19.0, npm 10.9.4 и Chrome 153.

```bash
cd frontend
npm ci
npm run build
npm run dev
```

Vite доступен на `http://127.0.0.1:5173`, `/api` перенаправляется на `http://127.0.0.1:8000`. Backend запускается отдельно по [общему README](../README.md). После сборки он также раздаёт `frontend/dist` по адресу `http://127.0.0.1:8000`. Для просмотра приложения с API используйте Vite или FastAPI: `npm run preview` не содержит API proxy.

## Оформление и навигация

- Светлая тема: тёплый молочный фон и шалфейный акцент. Тёмная: тёплый графит, винные кнопки и приглушённые розовые акценты.
- Стеклянные поверхности навигации и кнопок; поля и длинные тексты имеют спокойный фон. Иконки — встроенные SVG, шрифты — системные. Внешние CDN и новые зависимости не добавлены.
- При первом открытии учитывается системная тема. Явный выбор сохраняется в `localStorage` (`hattama-theme`) и синхронизируется между вкладками. Недоступность browser storage не мешает работать. `prefers-reduced-motion` отключает анимацию и плавный переход к источнику.
- «Обзор» показывает реальные серверные счётчики, последние встречи и локальные напоминания. Demo учитывается в счётчиках и явно помечается. При ошибке загрузки нет ложных нулей.
- На экране «Встречи» кнопка «Все встречи» раскрывает историю и поиск. В редакторе на широком экране поручения находятся слева, исходные реплики — справа. Участники и дополнительные замечания раскрываются отдельно. Панель сохранения/утверждения остаётся доступной при прокрутке.
- Текущий экран и ID встречи сохраняются в `sessionStorage`; содержимое протокола туда не записывается. Несохранённые правки живут в памяти вкладки. Перед закрытием нужно нажать «Сохранить».
- Диагностика открывается по статусу сервера в верхней панели. Доступность API не означает готовность или качество моделей.

## Совместимость с backend

Редизайн выполнен в `main` и сохранён при обновлении до `origin/main` `c3dc74a`. Backend, ML, fixtures и [контракт v1](../contracts/README.md) вручную не менялись. Типы и HTTP-маршруты сохранены; новые API не требуются. Входящее предупреждение о тестовом ML совмещено с новым дизайном, интеграционные тесты учитывают новую навигацию.

Сохраняются существующие правила: PATCH передаёт исходную `revision` черновика; approve — текущую серверную `revision`; `409` оставляет правки в интерфейсе с возможностью скачать резервный JSON. Пустая дата остаётся `null`, `due_text` редактируется независимо. Изменение протокола требует повторного утверждения. Просрочку и напоминания рассчитывает сервер.

Если реестр или напоминания загрузились, а метаданные встречи — нет, на каждой строке отображается «Источник не проверен · данные встречи недоступны». Это не позволяет demo-задачам незаметно выглядеть настоящими при частичном отказе API. После восстановления данных возвращается обычная маркировка.

## Проверка

Для воспроизводимой сквозной проверки без моделей доступен `npm run test:integration`: команда собирает UI и сама запускает отдельный временный backend. Требуются Python с `backend/requirements-dev.txt` (по умолчанию корневая `.venv`, другой путь задаётся `E2E_PYTHON`) и установленный Chrome. Запись видео здесь отключена, отдельный FFmpeg Playwright не нужен. ML подменяется явно маркированной заглушкой; сохранение, очередь, HTTP, ревизии, DOCX и интерфейс настоящие. Подробности — [инструкция стенда](../docs/TESTING_WITH_ML_STUBS.md).

Используйте отдельную тестовую базу: E2E создают вымышленные встречи и меняют их поручения.

```bash
# Из корня, при установленном backend-окружении
.venv/bin/python -m backend --port 8000 --data-dir /tmp/hatama-design-qa

# В отдельном терминале
cd frontend
npm run build
npx playwright install chromium
UI_BASE_URL=http://127.0.0.1:8000 npm run test:e2e
```

Для установленного Chrome: `npx playwright install ffmpeg`, затем добавьте `PLAYWRIGHT_CHANNEL=chrome` к команде тестирования.

**23.09.2026 после sync с `c3dc74a`: production-сборка успешна, 32/32 интеграционных теста с ML-stub за 2,2 минуты и 14/14 обычных E2E за 52,3 с.** В обычном запуске заглушек нет: недоступные реальные модели возвращают проверяемые ошибки. Проверены сохранение и reload, источники, сопоставление голосов, ручное добавление/удаление, очередь, перезапуск, настоящий конфликт `409`, утверждение, содержимое DOCX, исполнение, повторное утверждение, ошибки сети/моделей, валидация загрузки, клавиатура, предупреждение о закрытии, две темы и ширины 390/768/1024/1440 px. Тесты тем также проверяют системное предпочтение, сохранение выбора и отключённый storage. Частичный отказ списка встреч теперь имеет отдельный регресс маркировки.

Стадии обработки и аудиотаймкод проверяются отдельными управляемыми UI-тестами; это не измерение ASR. Реальные RU/KZ/смешанные текстовые входы в текущем окружении завершаются ошибкой недоступной модели. Эти негативные проверки пропускаются, если локальная LLM доступна. Полное описание границ — [QA](../docs/QA.md); трёхминутная защита — [demo.md](../docs/demo.md).

Playwright сохраняет отчёт, скриншоты и видео в `playwright-report/` и `test-results/`. Локальные снимки оформления — `artifacts/design-*.png`; эти каталоги исключены из Git.

## Ограничения

Проверен Chrome на macOS, включая узкие viewport; настоящие Safari/iOS/Firefox не проверялись. Это импорт готовых записей, а не подключение к Zoom/Teams/Meet. Напоминания локальные, без рассылки. Полный аудиопроход на реальных моделях и качество трёх языков этим редизайном не подтверждаются.
